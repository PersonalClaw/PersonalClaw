# Network-egress hosts — the machine-checked census of every routable hostname that
# appears as a literal in shipped PersonalClaw code (core `src/personalclaw/**/*.py` and
# the SPA `web/src/**/*.{ts,tsx}`) or in a shipped RECORD a fetcher reads its URL from (the
# bundled-model sign-off's `source_url`, the knowledge-source recipes' `spec`). The sweep
# test (tests/test_network_egress_hosts.py) fails if a routable host appears that is NOT
# listed here, and fails if a listed host no longer appears (stale entry).
#
# THE SECTION IS THE CLAIM, AND IT IS CHECKED. Each entry sits under one of four headers —
# fetched unprompted, fetched on the user's action, browser-side, never fetched — and the
# sweep cross-checks that against what the code can fetch: a host a shipped record fetches
# must sit in a FETCHED section, and a host a network-capable module holds as live data may
# sit under "Never fetched" only if its judgment names that module and says why it is not a
# request. `huggingface.co` sat under "Never fetched" while the bundled-model download and
# the Hugging Face token check both reached it; nothing noticed, because nothing read the
# sections.
#
# WHY THIS FILE EXISTS. PersonalClaw's privacy posture is "no telemetry, no phone-home":
# SECURITY.md and the website both say so, and it is true. Nothing enforced it. A new
# analytics endpoint, crash reporter, or "check for news" ping could be added in any PR and
# no test, lint or review checklist would notice — the claim was documentation, not a
# control. This table makes the destination list explicit, so adding a destination is a
# deliberate, visible act with a written justification.
#
# WHAT IT DOES NOT ANSWER. This is a census of DESTINATIONS, not of payloads. It cannot
# tell you what is sent to an approved host, and a new module reaching an already-listed
# host does not red the sweep. Static scanning cannot answer "what data left"; it can
# answer "is there somewhere new it could go", which is the question a phone-home is.
#
# Reserved and non-routable names are skipped by rule rather than listed, because a name
# that cannot resolve cannot be a destination: RFC 2606/6761 (`example.com`, `*.example`,
# `*.invalid`, `*.test`, `*.localhost`), loopback and RFC 1918 addresses, and `{...}`
# template placeholders.
#
# Format: <host> — <judgment>. State whether it is FETCHED and by WHOSE action.
#
# ── Fetched by the product, on its own initiative ──────────────────────────────
api.github.com — FETCHED, unprompted (when the check is enabled). The release-check endpoint (`self_update.py::fetch_latest_release`) and the GitHub feed source. WHEN: at every gateway start (`gateway.py::GatewayOrchestrator._check_for_updates`, on the boot path) and thereafter on the configured cadence when a dashboard update/system endpoint is hit (`updates.check_interval_hours` throttles `_do_update_check` via `dashboard/handlers/updates.py::_scheduled_check_due`) — there is no standalone background timer. Unauthenticated and ETag'd; it carries no user identifiers, but it does send a product-identifying `User-Agent` of `personalclaw-update-check`, and it reveals the instance's IP to GitHub. This is the closest thing in the product to a phone-home, and IT HAS AN OFF SWITCH (RUM-3): with `updates.check_enabled=false` the updater contacts api.github.com ZERO times — both `_do_update_check` (its `git fetch`) and `self_update.fetch_latest_release` return early before opening any network path, so a host set to that config makes no unprompted egress at all. `auto_update` is a separate, orthogonal control that gates only the unattended pull + rebuild + restart, not the check. When `updates.check_enabled` is on (the default), the check runs on the `updates.check_interval_hours` schedule as described; the kill switch is proven by `tests/test_self_update.py::test_fetch_latest_release_kill_switch_makes_zero_calls` and `test_do_update_check_kill_switch_runs_no_subprocess`.
# ── Fetched, but only because the user asked for that specific thing ───────────
codeload.github.com — FETCHED on `personalclaw app new`: downloads the app-template tarball. User-initiated, one-shot, never on a schedule.
hn.algolia.com — FETCHED only if the user enables the shipped Hacker News feed preset. A preset is a suggestion; nothing polls it until it is turned on.
news.ycombinator.com — the Hacker News preset's item-link host (see `hn.algolia.com`): the host its rendered rows link to, and the one the `hacker-news` knowledge-source recipe matches a pasted URL against. The preset polls the Algolia API, not this host.
api.anthropic.com — FETCHED only when the user points their OWN agent at the loopback capture proxy (`inbound/capture_proxy.py`), and then only as the relay destination for that agent's own inference request. Not PersonalClaw data and not a schedule: the product originates nothing here. It appears as a `_DIALECT_DEFAULT_BASE` string, used only when neither the agent's `X-PClaw-Upstream-Base-Url` header nor a configured ProviderEntry names an upstream, and the resolved base is still evaluated against the operator's allow-list — a default is a convenience, never a waiver. The proxy binds loopback only.
api.openai.com — FETCHED only on the user's own configuration, at two sites. (1) `inbound/capture_proxy.py`'s `_DIALECT_DEFAULT_BASE`: the relay destination for the user's OWN agent's inference request when they route it through the loopback capture proxy and name no upstream of their own — same shape and same allow-list guard as `api.anthropic.com` above. (2) `llm/catalog.py`'s `openai_compatible_discover_models` default base: an OpenAI-compatible provider the user configured with an API key and NO endpoint lists its models from `api.openai.com/v1/models`, through `net.fetch`, when the user opens its model list. Core ships no OpenAI credentials and no OpenAI provider (that lives in an app bundle); nothing here runs on boot or on a schedule.
doi.org — a RESOLVER url built from a DOI the user supplied in a knowledge source. Not fetched unless that source is fetched.
arxiv.org — the PDF url built from an arXiv identifier the user supplied. Same shape as doi.org.
ollama.com — FETCHED only when the user searches the model library from Settings → Models, and only from the BUNDLED `ollama-models` app (`apps/native/ollama-models/provider.py`, `OllamaCatalog.search_catalog`). It appears in this census for the first time because that app moved into core (an owner ruling, 2026-09-21); the code and the destination are unchanged, only the shipping tier is. Two GETs per search — `ollama.com/search?q=` and `ollama.com/library/<base>/tags` — scraped because Ollama publishes no JSON search API. STRICTLY user-initiated: nothing calls `search_catalog` on a schedule, on boot, or on install, and the provider's own `/api/tags` traffic goes to the user's OWN endpoint (loopback by default), not here. It sends a generic browser `User-Agent` and the typed query; no user identifier, no instance identifier, no telemetry. Fail-soft — a failure returns an empty candidate list, so the search box shows nothing rather than an error, and a host that blocks ollama.com loses model DISCOVERY only: pulling, listing, deleting and every chat turn go to the local daemon and are unaffected.
huggingface.co — FETCHED only on the user's explicit action, by two callers. (1) The bundled default chat model's one-time download: `apps/native/bundled-chat/provider.py::download_weight` GETs the `source_url` pinned in the shipped sign-off record (`apps/native/bundled-chat/bundled-model-signoff.txt`, the only copy) — only after the user accepts the download offer, which states the 138 MiB size first. The bytes are sha256-verified against the same record before anything runs them, and nothing starts the download on boot, on install or on a schedule. (2) The Hugging Face token check: `local_models/hf_token.py` sends the token to `huggingface.co/api/whoami-v2` through `net.fetch` (CONNECTOR policy) — only when a token is present (the credential store, `HF_TOKEN`, or the `huggingface-cli` file), and only when the user opens Settings → Models (the token-status row, or a gated model's download pre-check) or saves or clears a token; the verdict is cached for `local_models.whoami_ttl_s`. The request carries the token as a Bearer header and nothing else. Also present and never fetched: the sign-off record's `licence_url`, and the model-card CITATION links in `evals/voice_engine_bakeoff.py`'s evidence records.
github.com — FETCHED only when the user creates a watched knowledge source from a GitHub repository URL: the shipped `github-releases` recipe (`knowledge/sources/recipes/github-releases.json`) resolves it to that repository's `releases.atom` feed, which is polled only once the user has created the source. Everywhere else it is a LINK, not a request: docstring references to upstream specs (the Agent Client Protocol), the SPA's outbound link to an app's source, the release-notes link `dashboard/handlers/core.py` renders and `cli_server.py` prints, and the contact URL in `knowledge/connectors/web_url.py`'s `User-Agent`.
pypi.org — FETCHED only when the user creates a watched knowledge source from a PyPI project URL: the shipped `pypi-releases` recipe resolves it to `pypi.org/rss/project/<name>/releases.xml`, polled only once the user has created the source. Also an EXAMPLE url inside `triggers/web_poll`'s docstring, showing what a user's watch expression looks like.
www.reddit.com — FETCHED only when the user creates a watched knowledge source from a subreddit URL: the shipped `reddit-subreddit` recipe resolves it to `www.reddit.com/r/<name>/.rss`, polled only once the user has created the source.
# ── Browser-side, from an iframe the user's own content created ────────────────
cdn.jsdelivr.net — a CSP `script-src` entry and a `<script>` tag inside the artifact/widget iframe: Babel standalone, for transforming a react widget the agent produced. Loaded by the USER'S BROWSER, not by the gateway, and only when a react widget renders.
cdnjs.cloudflare.com — same iframe: the pinned React and ReactDOM UMD bundles.
cdn.tailwindcss.com — same iframe: Tailwind's browser build, for an artifact that uses utility classes.
# ── Never fetched: namespace identifiers, DTDs and schema ids ─────────────────
www.w3.org — XML namespace identifiers, never retrieved: the SVG namespace on inline `<svg xmlns=…>` markup (the token page `dashboard/token_auth.py` serves, among others), and the Atom namespace `knowledge_providers/feed_source.py` uses to NAME the elements it parses (`{http://www.w3.org/2005/Atom}entry`). That module does fetch — the feed the user configured — but never this namespace: an XML namespace is an identifier, not a URL to retrieve.
schemas.openxmlformats.org — the WordprocessingML namespace, used to build ElementTree tag names when parsing a .docx locally.
json-schema.org — the `$schema` draft identifier stamped into the generated config schema.
www.apple.com — the PropertyList DTD identifier in the launchd plist header. Declared by every macOS plist; the DTD is not retrieved.
api.w.org — a WordPress REST-API link `rel` VALUE that `knowledge_providers/web_source.py` compares against when reading a page's `<link>` tags. That module fetches the page the user is watching; this string is only ever the right-hand side of an equality test, not a request.
169.254.169.254 — the cloud metadata address, named in `triggers/web_poll`'s docstring as the SSRF target its host guard exists to BLOCK. Listed because a security control that names its threat is worth keeping visible; the code refuses this address rather than fetching it.
# ── Never fetched: documentation and links ────────────────────────────────────
agentskills.io — named in a docstring as the source of the skill-manifest FORMAT the loader implements. The format is implemented locally; nothing is fetched.
docs.astral.sh — the uv documentation URL printed in an installer error message, so a user missing pip is told where to get uv.
esm.sh — an EXAMPLE url inside `artifacts/build.py`'s docstrings, naming the bare-URL import that the React artifact build REFUSES. Same shape as 169.254.169.254 above: the code's job is to block this, not reach it. esbuild silently treats `import x from 'https://esm.sh/lodash'` as external and bakes the URL into the output at rc 0 with no warning, so the build reads the bundler's own metafile and rejects any import left outside the bundle (`external_imports`) — a deployed artifact page must fetch nothing. The build itself never reaches the network either: the toolchain is discovered rather than installed, the argv is core-owned and fixed, and the child env comes from `sandbox.build_child_env` so it does not inherit the operator's proxy config.
