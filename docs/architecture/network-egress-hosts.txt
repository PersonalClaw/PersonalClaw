# Network-egress hosts — the machine-checked census of every routable hostname that
# appears as a literal in shipped PersonalClaw code (core `src/personalclaw/**/*.py` and
# the SPA `web/src/**/*.{ts,tsx}`). The sweep test
# (tests/test_network_egress_hosts.py) fails if a routable host literal appears that is
# NOT listed here, and fails if a listed host no longer appears (stale entry).
#
# WHY THIS FILE EXISTS. PersonalClaw's privacy posture is "no telemetry, no phone-home":
# SECURITY.md and the website both say so, and it is true. Nothing enforced it. A new
# analytics endpoint, crash reporter, or "check for news" ping could be added in any PR and
# no test, lint or review checklist would notice — the claim was documentation, not a
# control. This table makes the destination list explicit, so adding a destination is a
# deliberate, visible act with a written justification.
#
# WHAT IT DOES NOT ANSWER. This is a census of DESTINATIONS, not of payloads. It cannot
# tell you what is sent to an approved host, and a new module reaching an already-listed
# host does not red the sweep. Static scanning cannot answer "what data left"; it can
# answer "is there somewhere new it could go", which is the question a phone-home is.
#
# Reserved and non-routable names are skipped by rule rather than listed, because a name
# that cannot resolve cannot be a destination: RFC 2606/6761 (`example.com`, `*.example`,
# `*.invalid`, `*.test`, `*.localhost`), loopback and RFC 1918 addresses, and `{...}`
# template placeholders.
#
# Format: <host> — <judgment>. State whether it is FETCHED and by WHOSE action.
#
# ── Fetched by the product, on its own initiative ──────────────────────────────
api.github.com — FETCHED, unprompted. The release-check endpoint (`self_update.py::fetch_latest_release`) and the GitHub feed source. WHEN: at every gateway start (`gateway.py::GatewayOrchestrator._check_for_updates`, on the boot path) and thereafter at most once per 12 hours when a dashboard update/system endpoint is hit (`dashboard/handlers/updates.py::_UPDATE_CHECK_INTERVAL` throttles `_do_update_check`) — there is no standalone background timer. Unauthenticated and ETag'd; it carries no user identifiers, but it does send a product-identifying `User-Agent` of `personalclaw-update-check`, and it reveals the instance's IP to GitHub. This is the closest thing in the product to a phone-home, and TODAY THERE IS NO SWITCH THAT TURNS IT OFF: `auto_update` gates only the unattended pull + rebuild + restart — `GatewayOrchestrator._check_for_updates` runs the check BEFORE it reads `cfg.auto_update`, and the field's own config metadata says so ("update checks always run"). Any claim that this check is opt-out is false today; if an opt-out lands, this line and `tests/test_self_update.py::test_auto_update_gates_the_apply_not_the_check` move with it.
# ── Fetched, but only because the user asked for that specific thing ───────────
codeload.github.com — FETCHED on `personalclaw app new`: downloads the app-template tarball. User-initiated, one-shot, never on a schedule.
hn.algolia.com — FETCHED only if the user enables the shipped Hacker News feed preset. A preset is a suggestion; nothing polls it until it is turned on.
api.anthropic.com — FETCHED only when the user points their OWN agent at the loopback capture proxy (`inbound/capture_proxy.py`), and then only as the relay destination for that agent's own inference request. Not PersonalClaw data and not a schedule: the product originates nothing here. It appears as a `_DIALECT_DEFAULT_BASE` string, used only when neither the agent's `X-PClaw-Upstream-Base-Url` header nor a configured ProviderEntry names an upstream, and the resolved base is still evaluated against the operator's allow-list — a default is a convenience, never a waiver. The proxy binds loopback only.
news.ycombinator.com — same preset as above (the item-link host in its rendered rows).
doi.org — a RESOLVER url built from a DOI the user supplied in a knowledge source. Not fetched unless that source is fetched.
arxiv.org — the PDF url built from an arXiv identifier the user supplied. Same shape as doi.org.
# ── Browser-side, from an iframe the user's own content created ────────────────
cdn.jsdelivr.net — a CSP `script-src` entry and a `<script>` tag inside the artifact/widget iframe: Babel standalone, for transforming a react widget the agent produced. Loaded by the USER'S BROWSER, not by the gateway, and only when a react widget renders.
cdnjs.cloudflare.com — same iframe: the pinned React and ReactDOM UMD bundles.
cdn.tailwindcss.com — same iframe: Tailwind's browser build, for an artifact that uses utility classes.
# ── Never fetched: namespace identifiers, DTDs and schema ids ─────────────────
www.w3.org — the SVG XML namespace on inline `<svg xmlns=…>` markup. An XML namespace is an identifier, not a URL to retrieve.
schemas.openxmlformats.org — the WordprocessingML namespace, used to build ElementTree tag names when parsing a .docx locally.
json-schema.org — the `$schema` draft identifier stamped into the generated config schema.
www.apple.com — the PropertyList DTD identifier in the launchd plist header. Declared by every macOS plist; the DTD is not retrieved.
api.w.org — a WordPress REST-API link `rel` VALUE that `web_source` compares against when reading a page's `<link>` tags. A string equality test, not a request.
169.254.169.254 — the cloud metadata address, named in `triggers/web_poll`'s docstring as the SSRF target its host guard exists to BLOCK. Listed because a security control that names its threat is worth keeping visible; the code refuses this address rather than fetching it.
# ── Never fetched: documentation and links ────────────────────────────────────
github.com — repository links: docstring references to upstream specs (the Agent Client Protocol) and, in the SPA, the outbound link on an app's source. A link the user may click is not egress by the product.
agentskills.io — named in a docstring as the source of the skill-manifest FORMAT the loader implements. The format is implemented locally; nothing is fetched.
docs.astral.sh — the uv documentation URL printed in an installer error message, so a user missing pip is told where to get uv.
pypi.org — an EXAMPLE url inside `triggers/web_poll`'s docstring, showing what a user's watch expression looks like.
esm.sh — an EXAMPLE url inside `artifacts/build.py`'s docstrings, naming the bare-URL import that the React artifact build REFUSES. Same shape as 169.254.169.254 above: the code's job is to block this, not reach it. esbuild silently treats `import x from 'https://esm.sh/lodash'` as external and bakes the URL into the output at rc 0 with no warning, so the build reads the bundler's own metafile and rejects any import left outside the bundle (`external_imports`) — a deployed artifact page must fetch nothing. The build itself never reaches the network either: the toolchain is discovered rather than installed, the argv is core-owned and fixed, and the child env comes from `sandbox.build_child_env` so it does not inherit the operator's proxy config.
api.openai.com — the default base url for an OpenAI-COMPATIBLE endpoint, in `llm/catalog` and in `inbound/capture_proxy.py`'s `_DIALECT_DEFAULT_BASE`. Core ships no OpenAI credentials and no OpenAI provider (that lives in an app bundle), so the catalog site is a default STRING only. The capture-proxy site CAN be reached, but only when the user routes their own agent through the loopback proxy and names no upstream of their own — see `api.anthropic.com` above, same shape, same allow-list guard.
