# Where PersonalClaw declares its OWN licence.
#
# RET-5. README.md and SECURITY.md carry a dated commitment that this project is MIT, has no
# CLA, sends no telemetry, and never relicenses an already-published release. This file is
# the structural half of the first part of that promise: an exact mirror of every place in
# the tree that states a licence identifier about THIS project, each with a judgment saying
# what the declaration is for and who reads it.
#
# `tests/test_licence_governance.py` enforces the mirror in both directions — a new
# declaration site reds, and a stale entry reds — so the table cannot quietly accumulate or
# quietly shrink. Every identifier here must be `MIT`.
#
# Three things that rail checks about a licence FILE, which are three different claims and so
# three different assertions. The IDENTIFIER (`MIT`), the GRANT (sha256-pinned against the
# root file's body, whitespace-collapsed, copyright line excluded), and the HOLDER. The holder
# is checked twice: every licence file in this tree must name `PersonalClaw contributors`, and
# — the rule the app scaffolder broke — no licence file may name the app BESIDE it as its
# holder. `personalclaw app new` used to fall back to the app's display name when `--author`
# was omitted, so four published exemplar repositories shipped `Copyright (c) 2026 Channel
# Null`: a grant naming an artefact, which holds nothing and points at nobody to ask.
#
# Format: <path> — <judgment>
#
# NOT here, by rule rather than by omission: `package-lock.json` and the other lockfiles.
# They record OTHER projects' licences (MPL-2.0 appears there today), so a non-MIT
# identifier in a lockfile is correct and says nothing about this project's terms.

LICENSE — the licence itself. The only artifact that grants anyone anything; its grant text is sha256-pinned by the rail so a rewrite that keeps the "MIT License" title still reds. The pin is taken from THIS file's body, and every other licence file in the tree is measured against it — so "MIT" means the same bytes in all six, not six files that each start with the same title.
pyproject.toml — the wheel's declared licence, in both `license` and the trove classifier. This is what PyPI shows and what every `pip install personalclaw` records in its dist-info, so it is the copy the largest number of users actually see.
packages/personalclaw-client-py/pyproject.toml — the `personalclaw-client` wheel's declared licence, in both `license` and the trove classifier. A SECOND separately published distribution, so it has its own dist-info and its own PyPI page; a licence change here would land on installers who never installed the main package. Found by the sweep, not by hand — it was missed by a manual census of "the pyproject" written the same day.
README.md — the shields.io badge in the header. The first licence statement a visitor reads, and the one a screenshot of the repo carries.
src/personalclaw/apps/native/ollama-models/LICENSE — the bundled Ollama provider app's own licence file, carried in with the app when it moved into core (an owner ruling, 2026-09-21). It IS this project's grant, not a third party's: the app was written by this project and its copyright line reads "PersonalClaw contributors", so it belongs in this mirror rather than under the lockfile exemption. WHO READS IT: the app platform treats a `LICENSE` beside `app.json` as the app's declared terms, and two CI rails enforce that — the apps repo's `manifest-validate` job requires a LICENSE beside every `app.json` and reds when a manifest's declared `license` disagrees with the file's first line, and the registry's `validate_registry.py:check_license` blocks a listing whose repo has no licence file or whose `app.json` omits one. (Corrected 2026-09-23: this entry used to name the Store consent card and `apps/quality.py` as the readers. Neither reads a licence — `apps/quality.py` contains the string zero times, and the Store card renders permissions and quality badges only. The readers above were verified in code.) An app also keeps its licence file when it is exported or re-published, so this is the copy that travels to anyone who takes the bundle out of the wheel. Kept for that reason rather than deleted as a duplicate of the root LICENSE: a bundled app that ships without one would read as unlicensed the moment it left the distribution.
src/personalclaw/apps/native/bundled-chat/LICENSE — the bundled default-chat-model app's own licence file (OU-14). Same judgment as ollama-models above, and byte-identical to it: the app's code was written by this project, its copyright line reads "PersonalClaw contributors", and the two CI rails named in that entry read a `LICENSE` beside `app.json` the same way for this app. WHAT IT IS NOT: the MODEL's licence. That is Apache-2.0, belongs to a third party, and lives separately in `weights/MODEL_LICENSE` + `weights/MODEL_NOTICE` (recorded in `docs/architecture/bundled-model-signoff.txt`, not in this census — this file mirrors declarations about THIS project's terms only, which is why the model's Apache-2.0 does not appear here and its absence is not an omission). Both files ship in the wheel and the first-run fetcher copies the model pair next to the downloaded weight, so on a machine that holds the bytes the app's MIT grant and the model's Apache-2.0 grant stay two separate files rather than collapsing into one.
desktop/package.json — the Electron app's manifest licence. Read by electron-builder and embedded in the packaged desktop artifact's metadata, so it travels to users who never see the repo.
staged-repos/app-template/LICENSE — the licence copied into every app scaffolded from the template. Not this project's grant, but it is the licence the template PROPAGATES to third-party app authors, so a change here changes what new apps ship under.
staged-repos/registry/fixtures/apps/clean-app/LICENSE — an app-registry validation fixture. Listed because the registry's own licence checks read it, so a change would silently move what the validator treats as an acceptable app licence.
staged-repos/registry/fixtures/apps/warning-app/LICENSE — an app-registry validation fixture for the `warning` scan verdict. Same reason as clean-app: the validator's expectations are calibrated against these bytes.
staged-repos/registry/fixtures/apps/dangerous-app/LICENSE — an app-registry validation fixture for the `dangerous` scan verdict. Same reason: it pins that a dangerous app is judged dangerous on its CODE, not on its licence.
