# PersonalClaw mobile shell

A [Capacitor](https://capacitorjs.com/) app whose entire job is to hand a native WebView one URL:
`<your-gateway>/#/companion`, the route this repo's gateway already serves.

It contains **no copy of the companion UI.** No components, no styles, no build of `web/`. The
phone shows exactly what a phone browser pointed at your gateway would show, because it *is* that
— loaded from your gateway, at runtime. Everything in `www/` is one screen asking for an address.

## Why it lives in this repository

The shell is a thin wrapper over a **route this repo serves**. Splitting it into its own
repository would put a release boundary between a URL and the thing that serves it: the companion
route, its pairing routes (`/pair`, `/api/devices/pair/*`), the session-cookie contract, and the
device registry in `web/src/lib/endpoints.ts` all live here and all move together. A separate repo
would mean a cross-repo version matrix for a change as small as renaming a hash route — and the
first drift would be silent, because nothing would build both sides at once.

Concretely, it earns its place in the workspace three ways that a sibling repo could not:

- `tests/test_mobile_shell.py` asserts the shell's route string against the route
  `web/src/app/App.tsx` registers, and its registry vocabulary against `endpoints.ts`. Those rails
  are only possible with both sides in one tree.
- `tests/test_ci_tier_enforcement.py` requires every tested npm workspace to have a root
  `test:<name>` script and a CI step, so `mobile/`'s tests cannot quietly stop running.
- One `npm ci` at the repo root installs it, like `web/` and `desktop/`.

The cost is honest and small: `mobile/` adds **27 MB / 93 packages / ~12 s** to a root `npm ci`
(measured), all of it the Capacitor CLI and its Ionic/`native-run` dependencies. Nobody needs it to
work on the backend or the dashboard, and it is a rounding error beside `desktop/`'s Electron.

## Layout

```
capacitor.config.json   native config: webDir, the navigation rail, the two safe-area keys
www/index.html          the bootstrap screen — the shell's ONLY UI
www/shell/network.mjs    which URL to open, and which hosts may be opened
www/shell/registry.mjs   the saved-gateway registry (format owned by web/src/lib/endpoints.ts)
www/shell/safeArea.mjs   reads the resolved insets and applies them to the bootstrap screen
www/shell/boot.mjs       wiring: remembered gateway -> companion, or ask for an address
test/*.test.mjs          `node --test`, zero dependencies
ios/  android/           GENERATED by `cap add`, never committed
```

No bundler and no build step: `www/` is plain ES modules, copied verbatim into the native app.
That is why nothing here imports a bare `@capacitor/*` specifier or anything from `web/`.

## The two things it configures

**Gateway URL.** Capacitor's usual "wrap a remote site" recipe is `server.url` in
`capacitor.config.json`, which is baked at build time. Every gateway lives at a different private
address, so a baked URL would mean one store build per owner. Instead the bootstrap screen learns
the address once, saves it as an endpoint row, and navigates away; later launches skip straight
through. `server.url` is deliberately absent, and a test asserts it stays absent.

**Device session.** The shell stores **no credential at all.** `POST /api/devices/pair/complete`
answers with an httponly `Set-Cookie` (`pc_token_{port}`), so the session lives in the WebView's
own cookie jar where script cannot read it. When you scan a pairing QR, the shell hands the WebView
to the gateway's own `/pair` page and lets *that* do the exchange — which is the only way the
cookie lands in the jar the companion will read from. A native redemption would hold a session the
WebView could not use.

Saved gateways use the registry `web/src/lib/endpoints.ts` declares (`companion:endpoints`,
`{active, endpoints[]}`), because that module owns the format for every companion shell. This shell
is its first consumer. It writes one row; the N-gateway switcher and per-endpoint storage
namespacing are not reimplemented here.

## Navigation is fenced to your private network

`server.allowNavigation` lists localhost, `*.local`, RFC1918 (`10.*`, `192.168.*`, `172.16.*` …
`172.31.*`) and Tailscale MagicDNS (`*.ts.net`) — **not** `*`. Capacitor keeps navigation to those
hosts inside the WebView and kicks everything else out to the system browser, so a link in
rendered content cannot steer the app onto an arbitrary origin wearing the app's chrome.

If you reach your gateway through a public reverse proxy, add that host to `allowNavigation` **and**
to `PRIVATE_HOST_PATTERNS` in `www/shell/network.mjs` — deliberately, in a diff. A test asserts the
two lists agree, so changing one alone reds the gate.

The `172.` octets are spelled out one at a time because a glob cannot say "16 through 31", and
`172.*` would hand the shell most of a public /8. Tailscale is matched by MagicDNS name rather than
its `100.64/10` CGNAT range for the same reason.

## Safe areas

Two documents, two mechanisms:

- **The served companion** is the gateway's document, so the shell owns no CSS in it — and `web/`
  declares no `env(safe-area-inset-*)` and no `viewport-fit=cover`. It is inset **natively**, by
  `android.adjustMarginsForEdgeToEdge: "force"` (Android draws edge-to-edge from API 35; this
  margins the WebView back inside the system bars and the display cutout) and
  `ios.contentInset: "always"` (the WKWebView scroll view's content inset).
- **The bootstrap screen** is the shell's own document. `shell.css` resolves the four `env()`
  values into `--pc-safe-*` custom properties (script cannot read `env()` directly), and
  `safeArea.mjs` reads them back and writes them onto the layout element as padding, re-applying on
  rotation and resize.

The native keys are read by native code, so no test in this repo can prove they *render*. A real
device is the only proof, and that is recorded as a PARTIAL in
`docs/roadmap/plans/MOBILE-COMPANION.md` rather than claimed.

The bootstrap screen uses CSS system colors (`Canvas`, `CanvasText`, `AccentColor`, `Field`) and
invents no design token. PersonalClaw's design system lives in `web/` and is served; hand-copying a
palette here would be a second, drifting definition of the product's colors.

## Building

Tests need nothing but node, and run from the repo root:

```sh
npm ci                 # from the REPO ROOT — single-root lockfile (npm/cli#4828)
npm run test:mobile
```

The native builds need a real toolchain, so they are a maintainer step and not a CI tier:

| | Requires |
|---|---|
| iOS | macOS, Xcode (a full install, not just Command Line Tools), CocoaPods |
| Android | JDK 17+, Android SDK (`ANDROID_HOME`), Gradle via the wrapper |

```sh
# from the repo root
npm run add:ios     --workspace mobile     # generates mobile/ios/     (gitignored)
npm run add:android --workspace mobile     # generates mobile/android/ (gitignored)
npm run sync        --workspace mobile     # after any capacitor.config.json or www/ change
npm run open:ios    --workspace mobile     # then Run, on a device or simulator
npm run open:android --workspace mobile
```

`ios/` and `android/` are **generated** and gitignored. `cap add` copies a template out of
`@capacitor/{ios,android}` and `cap sync` rewrites parts of it from `capacitor.config.json`; a
committed copy is a fork of that template that drifts from the Capacitor version in
`package.json`. Regenerate rather than commit.

To see it working, run a gateway on your LAN (`make serve` binds `0.0.0.0`), read its address off
`personalclaw status`, and type that into the bootstrap screen. Store packaging — icons, splash,
privacy declarations, TestFlight/internal track — is `MC-10`, not here.
